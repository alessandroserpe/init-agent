# Product

## Register

product

## Users

Developers and repository maintainers checking local agent work between coding
sessions. The dashboard is opened alongside the editor on a desktop; narrow
windows must remain usable.

## Product Purpose

Make open work and verification evidence understandable without interpreting raw
metadata. Show what needs attention, what was checked and when evidence changed.
Success is fewer manual lookups, not more metrics or mandatory workflow.

## Brand Personality

Practical, clear, restrained. Preserve the existing project style. No external
visual reference requested by the user.

## Anti-references

Avoid walls of equally prominent statistics, decorative status cards, and warnings
that imply required work when it is conditional. Do not equate passing tests with
proof of task completion or measured agent productivity.

## Design Principles

- Prioritize work and verification, as confirmed by the user.
- Explain why a result needs attention and retain its historical outcome.
- Keep technical detail available through disclosure rather than upfront noise.
- Preserve read-only local access and current security boundaries.
- Reuse existing context; do not add mandatory preparation steps.

## Accessibility & Inclusion

No specialized requirements were requested. Use readable contrast, keyboard
navigation, visible focus, semantic labels, and reduced-motion support. Status
must be conveyed in words, not only color.
